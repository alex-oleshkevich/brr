Why Small Browsers Win

By Jane Doe

Running a browser for every task is wasteful. Most tasks need one page, a few clicks and a copy of the text, so a fresh process per task spends far more than it ever gets back.

A small, supervised browser that starts on demand and goes away when it is idle keeps memory flat and makes failures easy to see.

For the next step, read the follow-up essay on lease handoff, which covers how a second client takes over a tab.

Throughput comes from reuse, not from larger machines. A pool of warm browsers that clients borrow and return serves many more requests than one cold start each.
